## Commands
- Setup: `make setup` (uv)
- All static checks + unit tests: `make check`
- One test: `uv run pytest tests/path/test_x.py::test_name`
- Data contracts: `make data-check`
- Evaluate + compare to baseline: `make gate` (writes `metrics/current.json`)
- Train: `make train CONFIG=configs/base.yaml`

## Layout
- `src/{{pkg}}/data/` loaders + contracts · `features/` stateless transforms · `models/` training · `evaluation/` metrics + eval entrypoint
- `configs/` all hyperparameters and paths (`base.yaml`), gate thresholds (`gates.json`), team settings (`team.json`)
- `tasks/` agent task board — `BOARD.md` index, one `T-NNN-slug.md` per task
- `data/raw/` immutable inputs (not in git) · `data/processed/` regenerated by code · `experiments/` write-ups

## Conventions
- Split before fitting anything; learned preprocessing goes inside the model pipeline.
- No hard-coded hyperparameters, paths, or seeds — read them from `configs/`.
- Every transform and metric has a tiny-data test with hand-checked values.
- Notebooks are for exploration; move reusable logic into `src/` with tests.
- Commits: `T-<id>: <what>` for task work.

## Allowed without asking
- Run any `make` target except `rebaseline`, any `uv run pytest`/`ruff`/`mypy` command.
- Create branches and worktrees named `task/*`, commit on them, and merge approved task branches into `main` locally.
- Write to `artifacts/`, `metrics/current.json`, `experiments/`, and `tasks/`.

## Needs human approval
- `git push`, deploys, anything touching remote storage or `data/raw/`.
- Changing `configs/gates.json` or `metrics/baseline.json` (`make rebaseline`).
- Adding dependencies.

## Agent team
- Orchestrator (`claude --agent orchestrator`) plans tasks and dispatches workers; workers each run in their own worktree on `task/<id>-<slug>`; the supervisor reviews every branch before merge. Protocols: skills `orchestrate-team`, `worker-protocol`, `merge-train`.
- Read `tasks/<id>.md` before working on a task; keep its status current.

## Code Review Rules
### Data leakage
- Flag any `fit`, `fit_transform`, target encoding, or feature selection that can see validation/test rows.
- Flag features derived from the label or from information after the prediction time.
### Reproducibility
- Flag randomness without a seed from config, and hyperparameters or paths written as literals in `src/`.
### Evaluation integrity
- Flag changes to `configs/gates.json`, `metrics/baseline.json`, or deleted/skipped/loosened tests unless the PR says why and a human approved it.
### Data boundaries
- Flag loaders without a contract check, silent `dropna`/`fillna` without a logged count, and any raw data or secrets in logs.
